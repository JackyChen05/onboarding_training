# 2.4 核心业务功能

## 机顶盒业务矩阵

| 业务 | 关键测试点 | 高频缺陷 |
| --- | --- | --- |
| 直播（组播） | 换台时延、组播加入成功率、长时间收看 | 组播组老化超时花屏、高频换台泄漏 |
| 点播 | 起播时延、拖放、码率自适应 | 特定片源花屏、弱网重缓冲 |
| 回看 / 时移 | RTSP 会话、时间轴准确性 | 时移边界（节目头尾）异常 |
| EPG | 数据更新、翻页性能、海报加载 | 数据量大后卡顿 |
| 应用与中间件 | 第三方 APK 兼容、内存占用 | 长稳后内存泄漏 |

## 判据意识：概率型指标必须带样本量

以下指标都是概率型的（手册 1.5.3），报告里写「94%」不完整，要写「94%（47/50）」：

- 语音唤醒率、误唤醒率（音箱）
- 换台成功率、起播成功率
- 掉线率、重缓冲率
- 开机成功率、升级成功率

## 中屏音箱特有业务

端到端链路：采集 → 唤醒 → 识别 → 理解 → 执行 → 反馈（手册 3.4）。关键场景：

- **大声放音乐时三米外唤醒**——自激干扰下前端算法能否提取人声（章首问题 3）。
- 唤醒判据必须写清：几米、几度、环境噪声多少 dB、多少次成功几次算达标。
- 实操环境：ADB 开启方式、动态密码获取、串口接线见知识库《中屏音箱测试方法与注意事项》。
