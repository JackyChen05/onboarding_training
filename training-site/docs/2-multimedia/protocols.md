# 2.2 关键协议（IGMP / RTSP / HLS / DASH）

## 组播 IGMP：直播的底座

组播路由器通过 IGMP 了解每个接口网段上是否存在组播组接收者：有成员才转发，没成员就停止——这是 IPTV 直播省带宽的根本机制（知识库《IGMP基本协议&测试方法介绍》）。

要点：

- **单播 / 广播 / 组播**的区别先想清楚：组播介于两者之间，帧只传送给属于组播组的多个主机。
- **IGMP Snooping**：二层交换机监听 IGMP 报文，按组转发而非泛洪——光猫/路由器作为家庭网关时这个功能是必测项。
- **版本差异**：IGMPv1/v2/v3，v3 支持指定源组播（SSM），运营商 IPTV 常用。
- **典型缺陷**：组播组老化超时——看电视几分钟一次短暂花屏。测试时长短就观测不到低频事件（手册 3.2.4）。**高频换台组播泄漏**——快速换台后黑屏，手工换台频率不足以暴露。

测试实操：

- TestCenter 可仿真组播源与客户端，建 IPTV 测试拓扑（知识库《STC-TCC-340-0505-02-CN-组播测试例详解》《PON上线配置及TestCenter测试组播方法介绍》）。
- 抓包过滤 `igmp`，观察 Report/Leave/Query 交互。

## RTSP：点播与会话控制

RTSP（Real Time Streaming Protocol）负责流媒体会话的建立与控制（PLAY/PAUSE/TEARDOWN），媒体数据本身走 RTP/UDP 或交织在 TCP。

- 测试重点：会话建立时延、拖放（seek）响应、异常断开后资源释放。
- 回看/时移业务的核心协议。

## HLS / DASH：OTT 自适应码流

- **HLS**（Apple）：切片（.ts/fMP4）+ m3u8 索引；**DASH**（MPEG 标准）：MPD 描述 + 分片。两者都是 HTTP 拉流 + 多码率自适应。
- 测试重点：**码率切换逻辑**（弱网是否降档、恢复后是否升档）、**重缓冲率**（概率型指标，必须给样本量）、起播时延、CDN 节点异常切换。
- 与组播直播的本质差异：每个终端独立拉流，CDN 压力随用户线性增长；弱网体验靠自适应算法兜底。
