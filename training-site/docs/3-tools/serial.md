# 3.2 串口与系统日志抓取

## 为什么串口是生命线

嵌入式设备可观测性天然差（手册 2.2.6）：量产固件关闭调试接口、日志轮转覆盖、很多状态没有导出接口。串口往往是你能看到设备内部的**唯一通道**——而串口只有一个，多个人调试要排队。

## 串口日志工具（部门在用方案）

知识库《串口抓日志工具使用方法》：

- 硬件：串口抓包小板（含 SD 卡、纽扣电池）——日志直接存 SD 卡，电池维持晶振，掉电时间戳不清零。
- 接线：小板连接光猫串口（注意区分**烧写/通信串口**与**日志串口**，见《模组固件烧写方式及产测工具使用说明》：黑色 USB 为烧写及通信串口，小板为日志串口）。
- 移动定制机型的串口小板抓日志方法见《16、移动串口小板抓日志方法》。

## 系统日志的规范用法

1. **日志级别**：测试前先确认日志级别足够（debug/info），问题复现后再导出。
2. **时间戳**：抓日志前同步设备时间——没有时间戳的日志在跨模块定位时价值减半。
3. **留存现场**：复现问题后**先导日志再重启**——日志轮转会冲掉现场。
4. **长稳测试**：挂串口日志全程记录，配合内存/状态定期采样，趋势分析用。

## 设备救火：升级变砖后的恢复

升级错误版本可能导致设备反复重启、系统起不来、Wi-Fi 起不来——这时要用救火模式通过串口把设备救回。核心流程（以中兴微方案为例）：

**1. 备份校准参数（平时就要做，入库时完成）**

设备正常时先备份 Wi-Fi 校准文件，否则救火后射频参数丢失：

- 串口/telnet 登录后 `cd /wlan`，用 tftp 把 2.4G/5G 校准文件（如 MT7603E.bin、MT7613E_EEPROM.bin）导出到 PC。
- 恢复后用 `iwpriv wlan0 e2p`（2.4G）、`iwpriv wlan4 e2p`（5G）核对校准值。

**2. 进入救火模式**

uBoot 异常无法用 downver 下载版本时，需短接 debug 针从 UART 模式启动：

1. 短接 debug 针，PC 串口线接入，设备上电。
2. 串口输入 `X` → xmodem 发送 `uboot_uart.bin`。
3. 串口输入 `g` → xmodem 发送 `UBOOT.bin`。
4. uboot 传完后**立即回车**进入 boot 模式（防止板子重启）。
5. tftp 准备版本目录（`xxx_UPGRADE_BOOTLDR.bin` 改名为 `upgrade.bin`），串口 `downver version` 下载版本（建议升 2 遍），`reset` 重启。

**3. 恢复出厂参数**

升级后所有参数恢复默认，需重新写入 MAC/SN/CMEI/SSID/地区码等（`sk_test set_xxx` 系列命令），写完恢复出厂。

> 救火用的固件包（uboot/bin）与串口账号密码属于敏感资产，不进本站——实操时向导师或对应平台负责人索取。高安（安全启动）设备的救火流程另有专门步骤，见《电信高安救火步骤》。

## 验收 checklist（导师签核项）

- [ ] 独立完成串口接线（区分日志口与烧录口），抓到启动日志
- [ ] 用抓日志小板挂测 24 小时以上并导出完整日志
- [ ] 在日志中定位一次异常事件（如 OOM、watchdog 复位）并给出结论
- [ ] 说出「先导日志再重启」的原因
- [ ] 在导师指导下完成一次变砖设备的救火恢复（含校准参数备份与回灌）
