# 3.3 码流 / 媒体分析

## 目标

面对一个「花屏/无声/卡顿」的多媒体问题，能独立分析媒体文件或码流，判断问题在**码流本身**还是在**设备解码**。

## 基本方法

1. **先分层**：按 [2.1 分层定位法](/2-multimedia/arch) 把问题隔离到「码流/解码/输出」某一层，码流分析只在怀疑码流层时使用。
2. **看封装与参数**：容器格式（TS/MP4）、编码（H.264/H.265/AV1）、分辨率、帧率、码率、GOP 结构、音频参数。
3. **找异常点**：花屏对应的具体帧位置是否有码流错误（参考帧丢失、参数集异常）、时间戳是否连续（音画同步问题的关键证据）。
4. **对比基准**：问题片源 vs 正常片源，同一编码参数组合下是否必现——「特定编码参数组合下花屏」是典型失效模式（手册 3.3.3）。

## 与测试用例的配合

- 测试码流库不能只用「正常生成的样片」——**异常码流**（截断、错序、非法参数）是解码器健壮性测试的弹药。
- 码流分析结论是「码流问题还是解码问题」归属判定的证据：同一码流在参照播放器（如 VLC/ffmpeg 软解）上的行为对比。

## 验收 checklist（导师签核项）

- [ ] 用工具查看一个媒体文件的完整参数（封装/编码/帧率/码率/GOP）
- [ ] 分析一个花屏片源，定位到具体异常帧并给出码流层结论
- [ ] 用参照播放器对比验证一次「码流 vs 解码」归属判断

## DVBinspector：TS 流深度分析（签核手册第 6 项）

针对 IPTV/组播场景的 TS 流专业分析（《应届生试用期能力建设与签核手册》签核项）：

- [ ] TS 流 PSI/SI 表深度解析（PAT/PMT/SDT/EIT 等），验证路由器对 IPTV/组播流表信息的透传完整性
- [ ] 按 PID 统计各码流的码率占比和空包填充率，评估视频流转发带宽占用
- [ ] 检测连续性计数错误（CC Error）、同步字节丢失（Sync Loss）及 CRC 校验错误，定位转发导致的丢包或花屏
- [ ] 识别视频编码格式（H.264/H.265）、分辨率、帧率及 GOP 结构，辅助判断 MTU/MSS 设置不当导致的播放异常
- [ ] 对比分析组播（IGMP）和单播（RTSP/HTTP-FLV）流形态差异

测试含义：「组播花屏」类问题，用 DVBinspector 对比 OLT 侧与 LAN 侧的 TS 流——CC Error 出现在哪一段，丢包就在哪一段，直接把问题定到转发链路的具体环节（配合 [5.2 组播升级案例](/5-cases/field) 的定位思路）。

## IxChariot / iPerf3：吞吐性能测试（签核手册第 5 项）

签核手册对吞吐性能测试的五条能力要求：

- [ ] 多流吞吐量测试：构造 TCP/UDP 单流及多流，分别测试上行、下行及双向全双工吞吐量，评估转发极限
- [ ] 变参压力测试：调整包长度、TCP 窗口大小及测试时长，分析不同帧长下的线速转发能力与 CPU 占用关系
- [ ] 实时指标监测：记录吞吐量曲线、平均/最大时延（Latency）、抖动（Jitter）和丢包率（Loss）
- [ ] 真实业务模拟（IxChariot 特有）：内置业务脚本模拟混合流量下的吞吐表现，验证 QoS 保障效果
- [ ] 长稳压力测试：以 90% 吞吐量压力持续运行 12~72 小时，监测吞吐波动及内存泄漏/自动降频

## Imatest Master：图像质量测试（签核手册第 7 项）

带屏/摄像头类产品的图像质量客观测试工具（区别于主观目测）：

- **基础成像指标**：MTF/SFR 锐度、畸变、横向色差、色彩还原 ΔE、噪声、动态范围、阶调响应、均匀性（渐晕/坏点）等 30 余项，符合 ISO 12233、ISO 15739 标准。
- **多图卡兼容**：自动解析 SFRplus、eSFR ISO、X-Rite 色卡、星点图、枯叶图等 30 余种标准测试图，单张图完成多指标同步测试。
- **自动化**：批量图像处理、视频帧提取、自定义测试计划、Pass/Fail 自动判定，配套数据库批量管理测试数据。
- **多场景**：消费相机、工业相机、手机影像、医疗内窥镜等，Windows/macOS/Linux 全平台。

## 网络性能观测：Iperf

测吞吐/丢包/时延最轻量的工具是 Iperf（区别于 TestCenter/IXIA 这类重型仪表，Iperf 跑在普通 PC/设备上即可）。基本用法：

- **工作模式**：一台跑服务端（`iperf3 -s` 监听），一台跑客户端发起会话（`iperf3 -c <服务端IP>`）。
- **TCP 吞吐**：`iperf3 -c <IP>`——测带宽，支持多线程/多连接、自定义窗口、报告 MSS/MTU。
- **UDP 丢包与时延**：`iperf3 -c <IP> -u -b <带宽>`——指定带宽打 UDP 流，报抖动（jitter）与丢包率。
- **跨平台**：Windows/Linux/嵌入式设备通用，常用来快速验证「链路实际能跑多少」。

与重型仪表的分工：Iperf 用于**快速自测与定性**（这台设备/这条链路大概什么水平），TestCenter/IXIA 用于**精确基准与出报告**（RFC2544 套件、多流并发、标准化判据）。定位性能问题时先用 Iperf 快速分层定位是「设备本身」还是「链路/对端」，再决定是否上仪表精测。
