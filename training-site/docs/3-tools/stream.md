# 3.3 码流 / 媒体分析

## 目标

面对一个「花屏/无声/卡顿」的多媒体问题，能独立分析媒体文件或码流，判断问题在**码流本身**还是在**设备解码**。

## 基本方法

1. **先分层**：按 [2.1 分层定位法](/2-multimedia/arch) 把问题隔离到「码流/解码/输出」某一层，码流分析只在怀疑码流层时使用。
2. **看封装与参数**：容器格式（TS/MP4）、编码（H.264/H.265/AV1）、分辨率、帧率、码率、GOP 结构、音频参数。
3. **找异常点**：花屏对应的具体帧位置是否有码流错误（参考帧丢失、参数集异常）、时间戳是否连续（音画同步问题的关键证据）。
4. **对比基准**：问题片源 vs 正常片源，同一编码参数组合下是否必现——「特定编码参数组合下花屏」是典型失效模式（手册 3.3.3）。

## 与测试用例的配合

- 测试码流库不能只用「正常生成的样片」——**异常码流**（截断、错序、非法参数）是解码器健壮性测试的弹药。
- 码流分析结论是「码流问题还是解码问题」归属判定的证据：同一码流在参照播放器（如 VLC/ffmpeg 软解）上的行为对比。

## 验收 checklist（导师签核项）

- [ ] 用工具查看一个媒体文件的完整参数（封装/编码/帧率/码率/GOP）
- [ ] 分析一个花屏片源，定位到具体异常帧并给出码流层结论
- [ ] 用参照播放器对比验证一次「码流 vs 解码」归属判断

## 网络性能观测：Iperf

测吞吐/丢包/时延最轻量的工具是 Iperf（区别于 TestCenter/IXIA 这类重型仪表，Iperf 跑在普通 PC/设备上即可）。基本用法：

- **工作模式**：一台跑服务端（`iperf3 -s` 监听），一台跑客户端发起会话（`iperf3 -c <服务端IP>`）。
- **TCP 吞吐**：`iperf3 -c <IP>`——测带宽，支持多线程/多连接、自定义窗口、报告 MSS/MTU。
- **UDP 丢包与时延**：`iperf3 -c <IP> -u -b <带宽>`——指定带宽打 UDP 流，报抖动（jitter）与丢包率。
- **跨平台**：Windows/Linux/嵌入式设备通用，常用来快速验证「链路实际能跑多少」。

与重型仪表的分工：Iperf 用于**快速自测与定性**（这台设备/这条链路大概什么水平），TestCenter/IXIA 用于**精确基准与出报告**（RFC2544 套件、多流并发、标准化判据）。定位性能问题时先用 Iperf 快速分层定位是「设备本身」还是「链路/对端」，再决定是否上仪表精测。
