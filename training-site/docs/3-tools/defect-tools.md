# 3.5 版本与缺陷管理工具

## 版本管理：烧录与升级

嵌入式设备的「版本」分两条路径：

| 路径 | 工具/方式 | 场景 |
| --- | --- | --- |
| 本地烧录 | 烧写工具 + 烧录串口（如 ESP8266 DOWNLOAD TOOL，见《模组固件烧写方式及产测工具使用说明》） | 开发调试、救砖 |
| OTA 升级 | Web 页面上传 / TR-069 Download / 组播升级工具 / 大网升级服务器 | 版本测试主路径 |

要点：

- 烧录时确认 **bin 文件烧写位置、端口号、波特率**三项再点 start。
- OTA 测试的重点不是「能不能升成功」，而是「**升级失败之后会怎样**」——变砖率必须是 0（手册 2.5 要点 3）。断电点要选在危险窗口，而不是随手拔。
- 组播升级：注意跨地区返工时的**地区码**问题与外部型号丢失风险（《山东现场组播返工升级指导书》）。
- 远程循环升级可用服务器脚本自动化挂机（《通过服务器脚本进行TR069远程循环升级测试指导》）。

## 缺陷管理：TAPD 全流程

缺陷从提报到关闭的完整流程与规范见 [4.1 缺陷生命周期](/4-defects/lifecycle)。工具层面要求：

- 提报字段完整：标题（模块+现象）、版本、环境、复现步骤、概率、证据链附件。
- 缺陷状态流转及时：修复验证不过要 reopen 并说明。
- 关联用例：缺陷与测试用例/需求关联，支撑后续回归与度量。

## 验收 checklist（导师签核项）

- [ ] 独立完成一次串口烧录（三项参数自查后操作）
- [ ] 完成一次 Web/TR-069 升级，并执行一次升级中断电测试
- [ ] 在缺陷系统中独立提报一个符合规范的缺陷（含证据链附件），走完到关闭的全流程
