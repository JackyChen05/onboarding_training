## 案例 1：四川电信魔方插件不回单

知识库《31、四川电信魔方插件不回单问题分析》。

现象：现网设备插件不回单（管理平台收不到设备回执）。

学习要点：

- 平台类问题的定位路径：设备侧日志（插件是否执行）→ 网络通道（抓包看回执是否发出）→ 平台侧（是否收到未处理）。
- 分段确认法：每一段先证明「我这段是好的」，再往下走——和机顶盒分层定位是同一个思想。

## 案例 3：组播返工升级（山东/河北）

知识库《山东现场组播返工升级指导书》。

现象：湖北移动机型返工发往河北移动，需组播升级到目标地区版本。

学习要点：

- 返工三流程：组播升级 → 信息核对 → 注意事项确认。
- **跨地区返工必须改地区码**，否则升级后配置不匹配；注意外部型号丢失问题。
- 工具类操作的「检查清单」意识：每一步有可验证的产出。

## 案例 4：硬件加速双路径不一致（手册重点案例）

详见 [1.5 NAT 一节](/1-access/protocols#nat：多终端共享一个公网地址)——限速不生效、流量统计对不上、端口映射时灵时不灵，根因是硬加速路径绕过软件策略。测试方法：策略类用例开/关加速各跑一遍对比。

## 案例 5：夏天下午集中掉线（手册五约束叠加案例）

高温 → 光模块功率漂移 + 高分光比光衰边界 → 信噪比不足 → OLT 判掉线。实验室常温 + 标准光衰永远复现不出来。学习要点：**应力组合测试**的必要性——单独测每个变量都正常，叠加才出问题。

## 案例 6：PON 故障按指示灯与注册状态分层排查（中兴微方案排障手册）

来自《中兴微方案PON故障排查》（13 组内总结）——这份手册的价值在于把「上不了网」这种模糊报障，拆成**看指示灯 / 看注册状态就能定段**的结构化流程。以下是要点提炼（完整命令见原文档）：

**第一层：看面板指示灯定段**

| 现象 | 优先怀疑 | 第一段排查 |
| --- | --- | --- |
| POWER 灯不亮 | 供电/硬件 | 电源线路；代码 GPIO 调用是否对（对照原理图） |
| PON 灯闪烁 | 未注册完成 / 同 PON 口有长发光 ONU | 检查是否已注册；逐一拔掉同 PON 口其他 ONU 找长发光设备 |
| PON 灭 + LOS 闪 | 光路不通 | 光模块/光纤/分光器连接；BOSA 是否校准；光衰是否过大（清洁光纤连接处） |
| PON 灭 + LOS 常亮 | 长发光被 OLT 判流氓 ONU 踢下线 | 确认光模块是否长发光、单板是否校准 |
| PON 灭 + LOS 不亮 | 接错光纤（EPON 接了 GPON） | 核对 OLT 侧线卡类型是 EPON 还是 GPON |
| LAN 灯不亮 | 以太网连接未建立 | 网线/网卡/单板硬件；指示灯开关是否关闭；换个 LAN 口对比 |
| POTS 灯不亮 | VoIP 未注册 | 语音 WAN 是否拿到 IP、语音配置、抓语音报文、换设备同账号对比 |

**第二层：GPON 注册按 O1–O5 状态定位**（与 [1.2 注册与 OMCI](/1-access/omci) 的五阶段对应）

| 卡在哪 | 典型根因 |
| --- | --- |
| 一直在 O1 | 光纤链路不良、BOSA 未校准、收光功率异常（正常 -8~-28dBm）、GPON 板烧了 EPON 版本 |
| O1↔O2 跳 | 光太强（过载）或太弱；分光器 IN/OUT 光纤接反 |
| O2–O3 跳不到 O5 | 同线卡下有相同 SN 设备；SN/Vendor ID 不合规被 OLT 防互通 |
| 能到 O4 注册不上 | 光功率太弱、OLT 侧 deactivate 了 ONU、链路误码导致测距失败 |
| 到 O5 又跳回 O2 | SN/LOID 未在 OLT 手动认证；OMCI 同步失败 |
| 长光纤失败短光纤正常 | 光纤长度超 OLT 测距上限；BOSA 灵敏度问题 |

**学习要点**：报障不要一上来就抓包——先用「指示灯 → 注册状态 → 光功率数值」三层把问题圈定到某一段，再针对那一段深挖。这是分层定位思想在 PON 上的完整落地。

## 案例 7：升级变砖与跨运营商升级的救火要点（中兴微版本与救火说明）

来自《中兴微软件版本文件与救火说明》（13 组内总结）。这份文档把「版本文件长什么样、变砖了怎么救」讲清楚了，要点：

**1. 看懂版本文件名**：格式为 `运营商_机型_上行方式_中间件_wifi型号_扩展_CPU型号_版本号_文件类型.bin`。运营商 CT/CM/CU（电信/移动/联通）；CPU 131/132/133 多为 XGPON，127s/128s 为 GPON/EPON。文件类型决定用途：`UPGRADE_ALL.bin`（内核+文件系统+中间件，日常升级用）、`UPGRADE_BOOTLDR_ALL.bin`（全量包，救火用）、`BURNROM_*.bin`（烧录）、`UBOOT_UART.bin`+`NO_SKYWORTH_HEAD_UBOOT.bin`（救火）。

**2. 高安（安全启动）版本区分**：电信方案有高安版本，文件名开头带芯片类型；烧录必须用带 `SWITCH` 字样的烧录文件。判断是否高安：`cat /proc/capability/boardtype` 看 `secure_ver`（YES=高安），或看串口启动日志有无 non secure 字样。

**3. 跨运营商升级必变砖的坑**：移动↔联通↔电信互刷时，必须在 uboot 下先 `nand scrub.chip -y` 全擦 flash，再升级**带 uboot 的全量包**，否则重启变砖。

**学习要点**：救火操作前务必先备份校准参数（见 [3.2 串口与救火](/3-tools/serial)）；「变砖率必须为 0」是升级测试的硬判据，而救不回来往往是因为没擦 flash 或升级包没带 uboot。
