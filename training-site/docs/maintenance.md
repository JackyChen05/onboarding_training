# 维护规范：知识库更新如何同步到本站

## 内容架构原则

本站内容分两层，**更新策略不同**：

| 层 | 来源 | 更新频率 | 谁负责 |
| --- | --- | --- | --- |
| 主干正文 | 《嵌入式产品系统测试入门学习手册》《新员工试用期目标设定》 | 低（文档改版时） | 手册维护人 |
| 扩展阅读 | ima「测试知识库」摘编 | 中（知识库新增专题时） | 本站维护人 |

## 知识库 → 本站的同步规则

1. **摘编引用，不全量复制**：知识库资料在「扩展阅读」区以「标题 + 一句话摘要 + 出处」形式引用，原文留在 ima。知识库原文修订时本站无需改动，除非摘要不再准确。
2. **出处标注格式**：每条引用必须带作者与所在文件夹（如「《TR069_IPV6_RMS管理》- 总结资料2」），方便回查。
3. **同步范围限定**：只巡检以下培训相关文件夹，不做全库扫描（全库 834 条，全扫成本高且无必要）：
   - 总结资料（含应届生培训文档、IPTV产品相关、接入产品相关）
   - 总结资料2（37 个专题）
   - 测试工作规范
4. **同步节奏**：建议每月或知识库有大更新时执行一次「同步巡检」：让 AI 助手扫描上述文件夹的增量条目，生成「新增/变更清单」，人工确认后更新对应页面的扩展阅读区。

## 页面修改约定

- 每页对应 `training-site/docs/` 下的一个 `.md` 文件，改内容 = 改文件，提交即生效。
- 新增知识点页面时，需同步在 `docs/.vitepress/config.mts` 的 sidebar 中注册，否则导航不出现。
- 工具类页面的「验收 checklist」与《工具能力清单》保持一致，改动前先与导师确认。

## 本地预览与构建

```bash
cd training-site
npm run dev      # 本地预览（热更新）
npm run build    # 构建静态文件到 docs/.vitepress/dist
npm run preview  # 预览构建产物
```
