# 1.5 关键协议（DHCP / PPPoE / NAT / TCP / UDP / IP）

## 学习要求

这一节不是背 RFC，而是**能用抓包说明每个协议的实际行为**。每个协议至少要能回答：它在握手哪几步、每步长什么样、坏了时用户看到什么。

## DHCP：地址从哪来

四步握手：Discover → Offer → Request → ACK（DORA）。

- 测试重点：租约续租（T1/T2 定时器）、地址池耗尽、Option 字段（Option 60/61 厂商标识、Option 82 线路信息——运营商场景必测）。
- 典型缺陷：续租失败导致运行数天后断网；Option 60 校验逻辑错误导致特定运营商环境拿不到地址。
- 实操：用 Wireshark 过滤 `bootp`，配合 xcap 构造带特定 Option 的报文（知识库《wireshark和xcap使用分享》有完整实例：测试 dhcpd option 60 校验功能）。

## PPPoE：拨号上网

两阶段：Discovery（PADI/PADR/PADS 建会话）→ Session（PPP 封装，LCP 协商 → PAP/CHAP 认证 → IPCP 拿地址）。

- 测试重点：MTU/MRU 协商（1492 的由来）、断线重拨、认证失败码。
- 典型缺陷：PMTU 黑洞——能 ping 通（小包）但网页打不开（大包被丢）。连通性测试用小包 ping 会掩盖这个问题（手册 3.2.4 典型失效空间）。
- 实操：TestCenter 可建 PPPoE 流（知识库《PON上线配置及TestCenter测试组播方法介绍》）。

## NAT：多终端共享一个公网地址

- 测试重点：会话表容量、老化策略、ALG（应用层网关，FTP/SIP 等需要 ALG 才能过 NAT）、端口映射（UPnP/手动）。
- 典型缺陷：**NAT 会话表耗尽**——P2P 下载时网页打不开；表项老化策略有缺陷时表项缓慢累积，两周后满（资源边界 × 时间累积的交叉缺陷）。
- 硬件加速陷阱：开启硬加速后部分策略（QoS、流量统计、防火墙）可能被绕过——所有策略类用例必须开/关加速各跑一遍对比（手册 3.2.4 重点案例）。

## TCP / UDP / IP：基本功

- TCP：三次握手、重传、滑动窗口。测试关注：丢包环境下的吞吐下降曲线、连接异常中断（RST）后的状态清理。
- UDP：无连接，组播、语音、DNS 都靠它。测试关注：丢包率测量、乱序处理。
- IP：分片与重组（MTU 相关）、TTL、IPv6 邻居发现（ND）替代 ARP、SLAAC/DHCPv6/PD 前缀分发。
- IPv6 生命周期测试是常见盲区：只测初次获址，不测前缀续租——运行数天后 IPv6 静默失效（手册 3.2.4）。
