# 1.4 TR-069 / TR-369 远程管理

## TR-069 是什么

CWMP（CPE WAN Management Protocol，Broadband Forum TR-069）：运营商通过 ACS（Auto Configuration Server，自动配置服务器）远程管理用户侧设备（光猫、路由器、机顶盒）的协议。你在运营商工单里看到的「远程下发配置」「远程升级」「远程诊断」，底层都是它。

核心交互模型：

- **CPE 主动发起**：设备周期性 Inform 上报状态（心跳），或事件触发（首次启动、配置变更、重启）。
- **ACS 下发动作**：GetParameterValues / SetParameterValues（读写参数）、Download（远程升级）、Reboot、FactoryReset。
- **Connection Request**：ACS 需要立即联系设备时，通过 HTTP 触发设备回连。
- **数据模型**：TR-181（Device:2）参数树，每个可管参数都有唯一路径，如 `Device.WiFi.SSID.1.SSID`。

## TR-369（USP）：下一代

TR-369 定义 USP（User Services Platform），是 TR-069 的演进：

- 传输从 HTTP 换为 **MQTT / WebSocket / STOMP**，设备常连接、消息化交互，解决 NAT 后 ACS 无法主动触达的问题。
- 架构从「CPE + ACS」变为「Agent + Controller」。
- 数据模型沿用 TR-181，测试思路大量复用。

## 测试环境搭建（部门实战）

知识库中有完整的 TR-069 环境搭建指导，要点：

- 实验室常用 ACS 环境：`http://192.168.201.65/acs`（XACS）；域名场景 `http://www.skyworthacs.com/acs`（通过内网 DNS 静态表项解析）。
- 网关侧需建一条 TR-069 WAN 连接（如 VLAN 800），配置 ACS URL 与认证用户名/密码。
- **IPv6 / 双栈 RMS 管理**是常见盲点：办公网 v4 单栈无法验证 v6 场景，需选双栈 VLAN 搭建（详见知识库《TR069_IPV6_RMS管理》）。
- 远程循环升级可通过服务器脚本自动化挂机（详见《通过服务器脚本进行TR069远程循环升级测试指导》）。
- TR-369 MQTT 测试：broker 用 EMQX，通过 18083 控制台观察连接与消息（详见《TR369测试指导(MQTT-基于openwrt)》）。

## 测试关注点

| 场景 | 要点 |
| --- | --- |
| 注册上线 | 首次 Inform 的 event code、参数上报完整性 |
| 参数读写 | 下发后设备实际生效（不是只回成功）、重启保持 |
| 远程升级 | 断点续传、失败回滚、**升级中断电不变砖**（变砖率必须为 0） |
| Connection Request | NAT 后能否触达、STUN 场景（见知识库《TR069-Stun测试总结》） |
| 不同 WAN 模式 | 桥接/路由/多 WAN 下 TR-069 通道的独立性 |
