# 1.1 PON 架构（OLT / ONU / ODN）

## 为什么先学 PON

你测的光猫（HGU）是 PON 网络的终端。不理解 PON 的三层结构，就无法理解注册、OMCI、DBA 这些后续概念，也无法判断「掉线」问题发生在哪一段。

## 三层结构

PON（Passive Optical Network，无源光网络）由三部分组成：

| 组件 | 位置 | 职责 | 测试关注点 |
| --- | --- | --- | --- |
| OLT（光线路终端） | 运营商机房 | 汇聚多个 ONU 的流量，分配上行带宽，管理所有 ONU | 与不同厂商 OLT 的互通性 |
| ODN（光分配网络） | 机房到用户之间 | 光纤 + 分光器，无源器件，一分多（典型 1:32/1:64） | 光衰预算、分光比 |
| ONU / ONT（光网络单元） | 用户家里 | 光猫本体，光电转换，承载业务 | **你的主要测试对象** |

```
OLT（机房）──光纤──> 分光器（ODN）──光纤──> ONU（用户家光猫）──> 路由器/电脑/IPTV
                         │
                         ├──> ONU（另一户）
                         └──> ONU（再一户）
```

## 上下行的不对称

- **下行**（OLT → ONU）：广播方式，所有 ONU 都收到全部数据，各自按 GEM Port ID 过滤出自己的。
- **上行**（ONU → OLT）：TDMA 时分多址，每个 ONU 只能在 OLT 分配的时隙内发光——这就是 [DBA](/1-access/dba) 存在的理由。
- 常用波长：下行 1490nm，上行 1310nm；GPON 下行 2.5G / 上行 1.25G，XGS-PON 上下行对称 10G。

## 测试中的真实含义

- 「光功率」是物理层判据：接收光功率过低（如 < -27dBm）会导致误码、掉线。弱电箱里弯折过小的光纤、劣质冷接子都会吃掉光衰预算。
- 实验室复现「某小区夏天下午集中掉线」这类问题时，要同时控制温度与光衰两个变量（手册 2.4 节的五约束叠加案例）。
- 多 ONU 环境下的问题（如上行冲突、DBA 分配异常）在单 ONU 环境下测不出来——测试环境需要模拟多 ONU 场景。

## PON 理论吞吐为什么达不到标称速率

GPON 标称下行 2.5G / 上行 1.25G，但实测吞吐永远到不了——要理解开销结构才能判断「这个吞吐数字正不正常」。PON 有线吞吐的转发本质是**以太网帧 → GEM 帧**的封装过程（G.984.3 / G.989.3 定义），每层都要扣开销。

**理论吞吐公式**（来自《PON系统理论吞吐量计算说明》，D=实际带宽、L=测试包长、C=ONU 增删的包长，帧间隙+前导=20 字节、GEM 帧头=5 字节、XGEM=8 字节）：

- **GPON 上行** = (D×L) / (L+C+5)
- **XGPON 上行** = (D×L) / (L+C+8+0..3 字节 padding，需对齐 4 字节)
- **GPON/XGPON 下行** = (D×L) / (L+20−C)

关键点：

- **下行 C 的来源**：网关 LAN 口剥掉 4 字节 VLAN，下行实际帧变短——例如 72 字节包剥 4 字节后 68 字节，再加 20 字节前导。TestCenter 统计 tx load 时要据此反推真实发送流量。
- **上行额外开销**：TDMA 的保护间隔、PLOu 物理层开销、DBA 报告，多 ONU 时更明显。
- **小包吞吐更低**：每包固定开销占比随包长减小而升高。

测试含义：测 PON 吞吐先算理论上限作基准——实测明显低于理论值才有问题，拿标称 2.5G 当判据会误判。注意个别方案（如海思）实测可能超理论值，多因物理层/OMCI 开销被压缩，属实现差异。
