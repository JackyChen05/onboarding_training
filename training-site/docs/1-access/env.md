# 1.7 测试环境搭建与验收标准

## 实验室环境组成

接入产品测试环境的核心要素：

| 要素 | 设备/工具 | 作用 |
| --- | --- | --- |
| 上联仿真 | OLT（华为/中兴/聚为）、TestCenter | 模拟运营商 PON 网络与流量源 |
| 射频环境 | 大/小屏蔽房、程控衰减器、屏蔽箱 | 可控射频，保证 Wi-Fi 测试可复现 |
| 无线性能 | OCTOBOX、IXIA/C50、手机阵列 | TR-398 类性能与多终端并发 |
| 有线性能 | TestCenter（RFC2544 套件） | 吞吐/时延/丢包/背靠背基准 |
| 管理通道 | XACS / RMS（TR-069）、EMQX（TR-369 MQTT） | 远程管理业务测试 |
| 抓包观测 | Wireshark、xcap、串口日志工具 | 协议行为与日志证据 |

## 搭建验收 checklist

一套环境「能用了」的判据（自己逐项验证后再开始正式测试）：

- [ ] ONU 在 OLT 上注册到 O5 状态，光功率在正常范围
- [ ] TR-069 WAN 建立，设备在 ACS 上线，可完成参数下发
- [ ] 打流仪表到 DUT 的物理链路协商速率正确（千兆口不自协商成百兆）
- [ ] 屏蔽房内底噪达标，衰减器校准在有效期
- [ ] 串口日志可正常抓取，时间戳正确
- [ ] 所用仪表 License、测试套件版本与用例要求一致

## 自建测试服务器（无现成环境时）

很多专项测试需要自己在 Linux/PC 上搭服务器。四个高频场景：

| 服务器 | 工具/方案 | 用途 | 关键点 |
| --- | --- | --- | --- |
| DHCP 服务器 | Ubuntu + Kea | 模拟运营商 DHCP（含自定义 Option） | Kea 需编译安装（依赖 MySQL/Boost/log4cplus），注意 Ubuntu 版本兼容性——新版依赖冲突时退回 20.04 |
| 测速服务器 | Ubuntu + Speedtest（LAMP） | 搭建内部干净测速点，排除公网差异 | apache2 + php + 源码部署，需保存结果时配 MariaDB + phpmyadmin |
| 多功能软路由 | RouterOS（ROS） | 一机搭 DHCP/PPPoE/V6/VPN 服务器 | ROS 可模拟 untag/tag、DHCP option、PPP 四种认证、L2TP/PPTP VPN——验证协议栈的利器 |
| 点播/组播源 | VLC | 快速搭 RTSP 点播源/组播流 | 见《使用VLC搭建点播服务器指导书》 |

判据：自建服务器的价值在于**可控与可复现**——排除运营商现网变量，让被测设备的问题能稳定暴露。搭建后先用一台已知正常的设备验证服务器本身可用，再上被测设备。

## 验收标准：测试结果的判据从哪来

1. **用例预期结果**：每条用例的预期必须可判定——符合判定准则五要素（观测量 + 测量方法 + 判定门限 + 样本量 + 环境条件）。
2. **运营商入库规范**：电信/移动/联通各自的入库测试规范是硬判据（见 [典型案例 5.1](/5-cases/operator)）。
3. **过程阶段要求**：各阶段测试活动与出入口准则按部门《软件测试过程阶段要求》（接入网/电信/广电/海外四份，知识库「测试工作规范」文件夹）执行。
4. **出口准则与残余风险**：详见手册 4.5——出口准则不是「用例全跑完」，而是「残余风险被显式评估并接受」。
